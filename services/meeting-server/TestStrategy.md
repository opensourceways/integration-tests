#### 3.1.1 订阅会议链接功能（#395）

**需求链接**: https://github.com/agentic-develop-playground/backlog/issues/395

**对应TASK**: TASK1 - 优化 `_wrap_user_id` 方法，使用字典映射注入 sig_email_list

**测试点**：

1. API响应数据结构验证：返回数据中每个会议对象包含`sig_email_list`字段
2. 字段类型验证：`sig_email_list`为字符串或null
3. 数据源切换验证：不同配置下数据来源正确
4. 有邮件列表时展示逻辑：显示蓝色链接+帮助图标
5. 无邮件列表时展示逻辑：显示灰色提示文案
6. 订阅链接跳转验证：点击后跳转到邮件订阅页面
7. 帮助提示展示验证：点击帮助图标显示提示文案

**预期结果**：

- API返回的每个会议对象包含`sig_email_list`字段
- 有邮件列表时字段值为订阅链接URL字符串
- 无邮件列表时字段值为null
- 有订阅地址：显示可点击的"订阅会议链接"，hover时显示下划线，点击后跳转到邮件订阅页面
- 无订阅地址：显示灰色提示"该SIG组暂无会议订阅地址，请联系infra sig创建订阅链接"
- 帮助图标点击后显示提示："订阅此组织会议后，后续可例行收到对应会议通知"

**验证方式**：

- 调用会议列表API，检查返回JSON结构
- 验证字段数据类型
- 通过日志或监控确认数据源调用情况
- UI自动化测试或人工验证
- 检查页面元素是否存在且属性正确
- 验证点击跳转目标URL

**人工测试执行计划**：

- **执行时间**：功能开发完成后，集成测试环境部署时执行
- **执行责任人**：测试人员或开发人员自测
- **验收标准**：
  - 有订阅地址的会议显示蓝色可点击链接，hover显示下划线
  - 点击订阅链接正确跳转到邮件订阅页面
  - 无订阅地址的会议显示灰色提示文案
  - 帮助图标点击后显示提示信息
- **执行方式**：在测试环境手动操作，截图存档作为测试报告附件

#### 3.1.2 异常处理验证（#395）

**测试点**：

**预期结果**：

- 本地数据库查询失败时sig_email_list字段为null，会议列表正常返回
- 前端根据字段状态显示相应UI

**验证方式**：

- 模拟权限平台服务不可用
- 模拟数据库查询异常
- 检查API返回和前端展示

#### 3.1.3 边界值与特殊场景测试（#395）

**对应TASK**: TASK1 - 数据注入逻辑边界场景覆盖

**测试点**：

1. group_name参数为null时的API行为
2. group_name参数包含特殊字符（空格、斜杠、SQL注入字符）
3. group_name参数超长字符串处理
4. 重复订阅操作场景（快速连续点击）

**预期结果**：

- group_name为null时API返回正常响应，sig_email_list字段为null
- 特殊字符group_name被正确转义处理，不引发SQL注入或路径遍历
- 超长group_name被截断或返回合理错误码
- 重复操作不影响系统稳定性，不产生重复数据

**验证方式**：

- 构造包含特殊字符的测试用例
- 使用超长字符串测试边界处理
- 模拟快速连续请求验证幂等性

#### 3.1.4 异常输入与故障模拟测试（#395）

**对应TASK**: TASK1 - 异常场景降级验证

### 3.2 性能测试专项

#### 3.2.1 批量查询避免N+1问题（#395）

**对应TASK**: TASK1 - 批量查询避免N+1问题

**测试点**：

1. 批量查询group_name时只执行一次数据库查询
2. 字典注入复杂度O(n)，不产生性能退化
3. 多个SIG组会议列表查询性能对比

**预期结果**：

- 权限平台/数据库查询次数为1次（批量查询）
- 查询时间与会议数量成线性关系
- 与原循环查询方案对比，性能提升明显

**验证方式**：

- 通过APM或日志监控查询调用次数
- 性能基准测试记录查询耗时
- 代码审查验证批量查询逻辑

### 3.3 集成测试专项

#### 3.3.1 权限平台数据源集成（#395）

**测试点**：

1. `PERMISSION_PLATFORM.ENABLED=true`时正确调用权限平台接口
2. 权限平台返回数据格式正确解析：`{group_name: [{type: "mailing_list", obj: "url"}]}`
3. 批量查询所有group_name，避免N+1问题

**预期结果**：

- 配置启用时调用`permission_adapter_impl.get_groups_detail_by_group_names()`
- 正确提取mailing_list类型的obj字段作为订阅链接
- 只执行1次批量查询，不循环查询每个SIG

**验证方式**：

- 通过日志或APM确认调用次数和数据源
- 验证返回数据格式转换正确性

#### 3.3.2 本地数据库数据源集成（#395）

**测试点**：

1. `PERMISSION_PLATFORM.ENABLED=false`时正确调用本地数据库
2. GroupInfoDao查询返回数据格式正确：`{group_name: email_list}`
3. 批量查询性能优化验证

**预期结果**：

- 配置禁用时调用`group_info_dao.get_email_list_by_group_names()`
- 返回的字典映射正确注入到每个会议对象
- 批量查询性能符合预期（O(n)批量查询 + O(m)字典注入）

**验证方式**：

- 通过日志或APM确认调用DAO方法和次数
- 性能基准测试对比原方案与新方案

#### 3.3.3 数据一致性验证（#395）

**测试点**：

1. 同一SIG组的多个会议订阅链接一致
2. 不同SIG组的订阅链接正确区分
3. 空group_name列表时正常处理

**预期结果**：

- 同一group_name的所有会议对象sig_email_list字段值相同
- 不同group_name的订阅链接正确对应各自的邮件列表
- 无会议或无group_name时不报错

**验证方式**：

- 构造包含多个同SIG组会议的测试数据
- 验证字段注入逻辑和结果一致性

### 3.1 功能测试专项

> 参考测试设计方向
>
> - API 语义验证：验证 HTTP 状态码（2xx, 4xx, 5xx）的使用是否符合 RESTful 规范。
> - 边界与非法输入：验证大数据量、空字段、特殊字符及非法 JSON 格式的拦截能力。
> - 业务状态机闭环：验证资源从"创建中"到"运行中"再到"已释放"的全生命周期逻辑。

#### 3.1.1 外部会议导入接口（POST /api/v1/meeting/import）[PR #361]

**正常流程验证**：

- **对应 task**: TASK5（meeting-center: 新增 POST /api/v1/meeting/import 接口）
- **测试点**: 使用 maintainer/committer 账号调用导入接口，传入完整参数，验证返回 `id` 和 `is_external=true`。
- **预期结果**: HTTP 200，返回 JSON 包含 `id`（整数）、`mid`（字符串）、`is_external=true`。

**边界值验证**：

- **对应 task**: TASK5
- **测试点**:
  - topic 长度边界（128 字符）
  - join_url 长度边界（128 字符）
  - date 格式边界（YYYY-MM-DD）
  - start/end 时间边界（end > start）
- **预期结果**:
  - topic/join_url 长度在限制内返回 200，超限返回 400。
  - date 格式正确返回 200，非法格式（如 2026-13-01）返回 400。
  - end > start 返回 200，end < start 返回 400。

**异常场景验证**：

- **对应 task**: TASK5
- **测试点**:
  - 缺少必填参数（join_url）
  - join_url 非 URL 格式
  - 非 maintainer/committer 用户调用
- **预期结果**:
  - 缺少必填参数返回 400。
  - join_url 格式错误返回 400。
  - 权限不足返回 403 或错误码 STATUS_MEETING_IMPORT_NO_PERMISSION。

#### 3.1.2 外部会议查询接口（GET /api/v1/meeting/meeting/）[PR #361]

**正常流程验证**：

- **对应 task**: TASK6（meeting-center: 修改查询接口返回数据增加 `is_external` 字段）
- **测试点**: 导入外部会议后，查询该日期范围，验证外部会议出现在列表且 `is_external=true`。
- **预期结果**: 查询结果包含外部会议，`is_external` 字段值为 `true`。

#### 3.1.3 外部会议修改接口（PUT /api/v1/meeting/<id>/）[PR #361]

- **对应 task**: TASK3（meeting-platform: 修改现有 API update 适配外部会议逻辑）
- **测试点**: 调用 PUT 接口更新外部会议 topic，验证不发起第三方 API 调用。
- **预期结果**: HTTP 200，更新成功，数据库记录更新，无第三方 API 调用日志。

#### 3.1.4 外部会议删除接口（DELETE /api/v1/meeting/<id>/）[PR #361]

**正常流程验证**：

- **测试点**: 调用 DELETE 接口删除外部会议，验证直接删除数据库记录，不调用第三方取消接口。
- **预期结果**: HTTP 200，数据库记录删除，无第三方 API 调用日志。

#### 3.1.5 外部会议通知接口（GET /api/v1/meeting/notify/<id>/）[PR #361]

**异常场景验证**：

- **对应 task**: TASK3（meeting-platform: 修改现有 API notify 适配外部会议逻辑）
- **测试点**: 对外部会议触发通知，验证返回"外部会议不支持通知"错误。
- **预期结果**: HTTP 400 或错误码 STATUS_MEETING_EXTERNAL_NOT_SUPPORT。

#### 3.1.6 定时任务跳过外部会议 [PR #361]

**正常流程验证**：

- **对应 task**: TASK4（meeting-platform: 修改定时任务跳过外部会议）
- **测试点**:

- **预期结果**:

  - 无录屏记录生成。

- **预期结果**:

## 5. 执行建议

1. **单元测试（UT）**：由开发在代码提交前完成，覆盖 meeting-platform Application 层逻辑与 Serializer。
2. **接口测试**：使用 Python pytest 脚本（`test_cases.py`）在测试环境执行，覆盖所有功能验收点。
3. **集成测试**：在预览环境执行跨服务调用链路验证，确保 meeting-center 与 meeting-platform 联动正确。
4. **定时任务测试**：手动触发定时任务或等待定时执行后验证外部会议状态不变、无录屏记录。
5. **日志与错误码验证**：通过数据库查询（OperationLog）与接口返回验证。
